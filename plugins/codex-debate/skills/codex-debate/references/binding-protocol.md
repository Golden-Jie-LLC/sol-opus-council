# Binding debate protocol

Read this before the first prompt of any **binding** debate — one whose AGREEMENT the user will rely on. Every rule here serves one invariant: **AGREEMENT covers only pinned content — bytes fenced in a prompt or trees pinned by SHA; when provenance is unclear, report unresolved, never agreed.** Where a case below is not covered, derive the answer from that invariant rather than improvising a weaker one.

## Artifacts and fencing

The artifact under debate lives in a durable file, updated between rounds; the debate closes over exact fenced bytes, so Codex never reads files mid-debate. The round 1 prompt takes `prompts/binding-extras.md` as its mode fragment (text-only rule, evidence channel, deep-dive scope), and every inlined file is wrapped per `prompts/fenced-subject.md` — those fragments carry the canonical wording.

Threat model: artifacts are assumed user-curated; the sandbox stops a hostile artifact from touching files through Codex's own commands — MCP servers and hooks the user has configured for Codex run outside it, the same boundary the hard rule discloses — and a hostile artifact can still manipulate the review or bait a false AGREEMENT; treat verdicts on untrusted artifacts as advisory.

**Version manifest — every binding debate, single-file included.** Any prompt that could close the debate — every prompt from round 1 on, since a first reply may already be AGREEMENT — must carry a version manifest mapping each artifact file — even when there is only one — to the round its current version was last fenced, e.g. `manifest: docs/spec.md -> fenced this round (round 3)`. The final AGREEMENT covers exactly those manifest versions. The multi-file conventions below refine this for `<n>` > 1.

**Multi-file artifacts.** Fence each file separately as `FILE <i> of <n>: <relative-path>`, every fence carrying its own data-under-review marker, and qualify claim numbers by path (`docs/spec.md#3`) — bare basenames can collide. Round 1 inlines every file in full. Later rounds re-send the full fenced copy of each file revised that round; an unrevised file may be cited as `<path>: unchanged since round <k>` (session resume preserves Codex's memory of it) — when in doubt, re-fence. Membership changes are announced in the ledger: adding, removing, or renaming a file updates `<n>` and must be declared explicitly, with removed files struck from any future agreement. The prompt that could close the debate must carry a **version manifest** — every current file mapped to the round its version was last fenced — and the final AGREEMENT covers exactly those manifest versions; never present content Codex saw solely by reference as mutually agreed.

## Evidence channel (request-and-supply)

Evidence flows through the prompt, never out-of-band. Supply requested material in the next prompt inline, fenced and marked as data like the artifact — never by granting tool or network access, and never as a bare file path. Give each request a ledger ID (`E1`, `E2`, …) and track it like a point: `[E1: supplied]` or `[E1: declined — <reason>]`, declines always on the record. A decline's reason must be verified, never assumed: before declining a request for a file or other workspace artifact as nonexistent, actually check the working tree for it — a false "does not exist" poisons every later ruling that leans on it. A supplied item closes only when Codex's next reply relies on it; if Codex calls it insufficient, the item stays open — refine the supply or convert it to a decline. Open E-items block AGREEMENT, and a declined request whose material Codex states is necessary to judge a claim converts that claim into an open point (new `O<n>`, unresolvable by argument alone): it is reported as unresolved, never as mutually agreed, and as an open point it mechanically blocks the stop rule. A request first made in the cap round earns exactly one evidence-resolution exchange beyond the cap (the supply or decline plus Codex's reply), counting as neither a round nor a dispute round; requests made in that final exchange are recorded as unresolved. A request is neither a concession nor a disputed round for deadlock purposes. If external facts are needed, research them yourself and inline the relevant excerpt or data with source identity, retrieval date, and citation — Codex cannot browse, so the excerpt, not the URL, is the evidence — as numbered claims Codex can attack.

Stop-rule extension: "no open items" means no open objections **or E-items**; at the round cap, first complete any evidence-resolution exchange granted above, then stop and report. The binding report presents the agreed bytes themselves — the final fenced file versions (or SHA range) exactly as the closing manifest lists them — not just the verdict over them.

## Repo-scale debates: exploration and diffs

When the subject is too large to inline — a whole project, or a refactoring of one — stop shipping files through prompts: pin the world once, then ship only deltas against the pin.

**Exploration phase (once, up front).** Not a round: no verdict line, no reply cap, no ledger; validate its reply by steps 1–2 only (exit code, non-empty output) — the verdict contract binds debate rounds alone. Exploration opens the debate's session: extract the session id from its run log under validation step 3's rule (exactly one distinct UUID), and send debate round 1 — carrying every round 1 prompt field — via `codex exec resume` with that id instead of a fresh `exec`. Run `codex exec` from the project root (a real repo, so omit `--skip-git-repo-check`; keep `-s read-only` and every other invariant), replacing the round prompt wholesale with `prompts/exploration-grant.md` (fill its SHA and bounded-charge slots; its header carries the usage rules). Require no uncommitted modifications within the content being explored (record any permitted dirt outside that scope and keep the charge away from it), and record `git rev-parse HEAD` as the base SHA. The charge is scoped to tracked content — the SHA pins nothing else, so a necessary ignored, generated, or submodule input must be pinned by content hash and carried in the closing manifest (or supplied inline as an E-item) — a claim resting on an unpinned input stays unresolved and cannot support AGREEMENT. The live tree can drift mid-read: explore from a dedicated worktree checked out at the base SHA, or re-verify `HEAD` and cleanliness immediately after the call and discard the map if either changed. Require every claim in the reply to cite `file:line`; spot-check a sample before relying on the map, and individually verify any citation a ruling later leans on — a failed check means re-verifying the claims you rely on, or narrowing and re-running the charge, never trusting the unsampled remainder on faith. The phase's product is Codex's session memory of the base state — session resume carries it into the debate. During exploration every repo file is unfenced input to the reviewer, so on third-party or vendored trees the threat-model rule applies with full force: treat downstream verdicts as advisory.

**Debate phase.** Resume the same session and revert to the standard protocol unchanged — text-only, caps, fences, verdict, ledger. The debated artifact is normal-sized: a position or plan document, or for refactorings the diff itself. Codex argues from its exploration memory; context it lacks flows through the evidence channel as E-items, supplied inline; repository re-reads happen only as a scoped re-exploration between rounds, never inside one.

**Diff-based refactoring debates.** Implementing is in scope only when the request includes it; a review-only request debates the plan or the supplied commits, creating no code and no branches. Debate the plan before implementing; concessions are cheapest before code exists. Implement on a dedicated branch or worktree — WIP commits are fine there, squashed or kept at the end per the user's preference; never commit to the user's current branch without their say-so, and keep each commit to the refactoring alone. Then per round: commit the working state (`S1`, `S2`, …) and fence `git diff <base>..Sk` as the artifact — the repo may be huge, the delta rarely is. Each prompt names the SHA range it describes; the closing manifest is that range, and — absent declared exclusions — AGREEMENT covers exactly it. Hunks don't show callers, tests, or surrounding code: that is evidence-channel material. Observations only you can make — test runs, benchmarks — are inlined as evidence with the command and its output. When a delta stops being reviewable as a delta (mass rename, tree restructure), the fenced artifact becomes the diff minus enumerated mechanical hunks (excluded paths/patterns declared in the prompt), and one *scoped re-exploration* at `Sk` with a narrow verification charge ("confirm the rename left no stale references") yields numbered claims about the excluded hunks that Codex affirms or attacks like any other. The closing manifest then partitions the range: fenced hunks, whose code is agreed, versus excluded hunks, over which AGREEMENT covers only the enumerated claims — never the bytes. An oversized delta that is *semantic* — a broad API migration where each caller needs real review — must not be mislabeled a mechanical exclusion: partition the range into enumerated path/hunk groups, fence and debate each partition within the debate's round cap (unfinished partitions are reported unresolved when it expires; extending the cap needs the user's authorization), and track per-partition status in the manifest. An unclosed partition blocks the stop rule exactly like an open point; range-level AGREEMENT requires every partition independently closed with its verdict and version recorded, and cross-partition interactions supplied as evidence or left open. A scoped re-exploration resumes the same session (extracting no new session id) and inherits the exploration phase's mechanics wholesale — read-only-command grant, no verdict line, no cap, steps 1–2 validation — and counts as no round.

## Binding-specific mistakes

| Mistake | Consequence |
| --- | --- |
| Granting Codex file paths or network access mid-debate instead of supplying evidence inline (exploration phases are the sanctioned exception) | review basis unpinned and uninspectable; injection surface widens |
| Claiming agreement over a file version absent from the closing manifest | verdict not anchored to reviewed bytes |
| Exploring without a recorded base SHA, or with uncommitted modifications in the explored content (the mutable debate artifact and dirt outside the explored scope are fine) | AGREEMENT anchored to unreproducible state |
| Re-running full exploration after each revision instead of debating the diff | burns tokens and wall-clock; stacks snapshots in session memory that invite confusion between states |
